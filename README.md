# Расписание занятий УМПК

Сайт расписания Уфимского многопрофильного профессионального колледжа:
<https://umpksch.ru>

Каждые полчаса GitHub Actions скачивает excel-таблицы из публичной папки облака
Mail.ru, разбирает их и обновляет `docs/data/schedule.json`. Этот файл и есть
всё расписание — около 50 КБ в сжатом виде. Сайт статический, сервер ему
не нужен: браузер забирает файл одним запросом и дальше работает сам.

* Мобильная и компьютерная версии — одна адаптивная вёрстка.
* Студент выбирает группу (поиск или список), видит расписание на сегодня,
  завтра и всю неделю; вкладки подписаны датами.
* Во вкладке «Неделя» неделя выбирается кнопками «1 неделя», «2 неделя» …
  Показываются только те недели, у которых в таблицах проставлены даты —
  сейчас их две. Появятся новые — кнопки добавятся сами.
* Преподаватель выбирает себя из списка и видит свои пары с указанием
  группы и аудитории.
* Чётность недели («1 неделя» / «2 неделя») считается автоматически.
* На главной под строкой о текущей неделе написано, когда сайт последний
  раз забирал таблицы из облака: «сегодня в 18:27», «вчера в 09:40» или дата.
* Три последних открытых расписания видны как «Недавние» — и на главной,
  и на страницах выбора группы или преподавателя.
* Расписание дня можно отправить картинкой — кнопка «Поделиться» открывает
  системное окно отправки, а где его нет, картинка скачивается.
* Идущая сейчас пара подсвечена, уже закончившиеся приглушены; отметки
  обновляются раз в минуту без перезагрузки страницы.
* Без сети сайт открывает сохранённую копию, а сверху поднимается полоска:
  расписание могло устареть, дата сборки указана тут же. Как только сеть
  возвращается, файл перечитывается и полоска гаснет.
* Светлая и тёмная темы — кнопка в шапке переключает одну в другую. Пока
  человек не нажал её ни разу, тема берётся из настроек системы; после
  нажатия выбор запоминается в браузере.
* Сайт можно установить как приложение на телефон и компьютер.

## Как это устроено

```
облако Mail.ru  ->  tools/build_data.py  ->  docs/data/schedule.json  ->  сайт
                    (GitHub Actions, каждые полчаса) (в репозитории)
```

Никакого сервера в работе нет. GitHub Actions запускает разбор по расписанию
и коммитит обновлённый файл, GitHub Pages раздаёт папку `docs`.

Запусков в расписании два в час — в 20 и 50 минут. Это не значит, что
расписание обновляется дважды в час: на бесплатном тарифе GitHub часть
запусков по расписанию пропускает, наблюдалось раз в 2,5–3,5 часа. Две
попытки вместо одной просто повышают шанс, что хотя бы одна пройдёт.
Ровные `:00` и `:30` не берём намеренно: в эти минуты очередь у GitHub
самая длинная. Когда обновление нужно сейчас — кнопка **Run workflow**
на странице Actions.

## Локальный запуск

```bash
python -m pip install -r requirements.txt
python tools/build_data.py     # скачать таблицы и собрать расписание
python -m http.server 8000 --directory docs
```

В Windows то же самое делают `install.bat`, `update.bat` и `run.bat`
(двойной щелчок). Сайт откроется на <http://localhost:8000>.

## Логотип

Логотип колледжа лежит в `docs/assets/`: `logo.png` — для шапки, `favicon.png` —
для вкладки браузера, `icon-192.png` и `icon-512.png` — для установки как
приложения. Рядом, в корне сайта, `docs/favicon.ico`. Все картинки собраны
из исходника скриптом:

```bash
python tools/make_logo.py "brand/Логотип 3. png.png"
```

Он обрезает прозрачные поля и уменьшает изображение — исходник на несколько
мегабайт в шапке не нужен. Если файлов нет, показывается векторная заглушка
из `docs/index.html`.

Иконки квадратные, и это важно: логотип — вытянутый ромб, и раньше
`favicon.png` сохранялся как есть, 57x64. Неквадратную иконку Google и Яндекс
пропускают — в выдаче рядом с сайтом рисовался стандартный глобус. Теперь
картинка вписана в квадрат и добрана прозрачными полями. `favicon.ico`
лежит именно в корне: поисковики и старые браузеры спрашивают
`/favicon.ico`, не заглядывая в разметку страницы.

## Установка как приложения

В шапке справа есть кнопка со стрелкой вниз — она показывает инструкцию
под то устройство, с которого зашли:

* **iPhone, iPad** — Safari, кнопка «Поделиться» → пролистать вниз →
  «На экран „Домой“». Работает всегда, даже по обычному http.
* **Android** — Chrome, меню ⋮ → «Установить приложение».
* **Компьютер** — Chrome, Edge, Яндекс Браузер: значок установки в адресной
  строке.

Важно: Android и компьютерные браузеры разрешают установку только с
`localhost` или по **https**. Пока сайт открыт по `http://192.168.…`,
кнопки установки в браузере не будет — приложение поставится лишь после
того, как сайт получит адрес с сертификатом. На iPhone это ограничение
не действует. Сам сайт по http работает нормально.

За установку отвечают `docs/manifest.webmanifest` и `docs/sw.js`.
Service worker ещё даёт офлайн-доступ. При установке он сохраняет и сам
`data/schedule.json`, поэтому расписание открывается без сети уже после
первого захода. После крупных изменений сайта поднимите номер
в `const CACHE = 'umpk-v9'`, чтобы старые файлы гарантированно вычистились.

Дальше файлы берутся сначала из сети и только потом из копии. Сеть при этом
ждём не дольше `NETWORK_TIMEOUT` (5 секунд): «интернета нет» и «сеть молчит» —
разные вещи, и при выключенном интернете, но живом wi-fi запрос не обрывается,
а висит минутами — всё это время экран был бы пустой.

Если сеть не ответила или ответила ошибкой, копия отдаётся с заголовком
`X-From-Cache` — по нему сайт понимает, что показывает сохранённое, и
поднимает полоску сверху. Ответ 404 или 5xx учитывается наравне с молчанием:
GitHub Pages в момент выкладки такое отдаёт, и раньше сайт показывал ошибку,
хотя рабочая копия лежала рядом.
Страницу, которой нет в копии, service worker подменяет на `index.html`, чтобы
открылась любая ссылка; для остальных запросов он отвечает ошибкой 504 —
подсунуть страницу вместо `schedule.json` значило бы уронить разбор.

Что сайт может показать без сети, видно на странице «О расписании»
(<https://umpksch.ru/#/info>), раздел «Работа без сети»: встал ли service
worker, сохранилось ли расписание, откуда открыт текущий экран. С телефона
это единственный способ понять, что происходит.

## Кэш браузера

GitHub Pages отдаёт файлы сайта с заголовком `Cache-Control: max-age=600`.
Заголовок его, поменять нельзя: десять минут браузер показывает файл из
своего кэша, вообще не спрашивая сервер. После правки сайта устройство всё
это время работает на старом `app.js` — и, что хуже, service worker при
установке тоже возьмёт из кэша старую версию и сохранит её у себя.

К `data/schedule.json` это не относится: его service worker запрашивает
с `cache: 'no-cache'` (функция `freshen` в `docs/sw.js`), то есть всегда
спрашивает сервер. Иначе после обновления расписания телефон до десяти минут
показывал бы прежние пары, считая их свежими. Трафика это не добавляет:
не изменился — придёт пустой ответ 304.

Если после правки сайта устройство всё же показывает старое, откройте адрес
с любым «хвостом» — например `http://<адрес>:8000/?new`. Это другой URL,
его в кэше нет, и страница подтянется заново. Убедиться, что версия свежая,
можно на странице «О расписании»: там есть строка «Версия сайта»
(`SITE_VERSION` в `docs/app.js`).

Поэтому ссылки на `styles.css` и `app.js` в `docs/index.html` помечены `?v=9`.
Заметно правите эти файлы — поднимите номер и там, и в `SHELL` внутри
`docs/sw.js` (номера должны совпадать). Новый адрес в кэше не значится, и
браузер сразу забирает свежий файл, не выжидая десять минут.

## Откуда берутся данные

Публичная папка облака: <https://cloud.mail.ru/public/KRh4/Q5UoGDxkv>

Сервис использует открытое API облака, авторизация не нужна:

| Шаг | Запрос |
| --- | --- |
| список файлов | `GET /api/v4/public/list?weblink=<ссылка>` |
| адрес отдачи  | `GET /api/v2/dispatcher` → `body.weblink_get[0].url` |
| файл          | `GET <weblink_get>/<weblink файла>` |

Скачиваются все `.xlsx` из корня папки (сейчас их пять). Оригиналы ложатся
в `data/raw/` и в репозиторий не попадают, разобранное расписание — в
`docs/data/schedule.json`.

Скачаться должны все файлы до единого. Четыре из пяти — это не «расписание
без одного файла», а расписание без пятой части групп: студенты этих групп
увидели бы «расписание не найдено», причём запуск в Actions был бы зелёный.
Поэтому недокачка тоже считается провалом сборки.

Если облако недоступно, файл не скачался или разбор упал, сборка завершается
с ошибкой и **файл сайта не трогает**: студенты продолжают видеть предыдущее
расписание, а в Actions появляется красный запуск.

## Настройки

Всё в `app/config.py`. Три переменные можно переопределить окружением:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `UMPK_CLOUD_LINK` | `KRh4/Q5UoGDxkv` | публичная ссылка на папку облака |
| `UMPK_HTTP_TIMEOUT` | `60` | таймаут скачивания, секунды |

Остальное правится прямо в файле: `GROUP_RENAMES` — исправления опечаток
в названиях групп, `SHEET_PREFERENCE` — какой лист брать при дублирующихся
вкладках, `COLLEGE_SHORT` и `COLLEGE_FULL` — название в шапке сайта.

## Структура исходных таблиц

Все пять файлов устроены одинаково:

```
строка 1     заголовок «Расписание занятий на I полугодие …»
строка 4     названия групп; каждая группа занимает 4 столбца, начиная с D
строка 5     подгруппы: столбцы c и c+1 — первая, c+2 и c+3 — вторая
столбец A    «Понедельник  31.08» — объединён на все строки этого дня
столбцы B, C номер пары и время
строка пары  дисциплина (объединена по ширине) + аудитория в c+3
строка ниже  преподаватель
```

Ширина объединения — это и есть признак подгруппы. Занятие всей группы
растянуто на все четыре столбца, занятие одной подгруппы занимает свою
половину. Когда в половине второй подгруппы пусто, отличить «пара только
у первой» от «пара общая, просто забыли объединить» помогает строка
преподавателя: её объединяют по фактической ширине занятия.

Листы `1 неделя` и `2 неделя` — нечётные и чётные недели. Занятия привязаны
к дню недели и чётности, а не к календарной дате. Если в книге один лист
(`П.xlsx`), его расписание считается одинаковым для обеих недель.

Даты в шапке дня решают две задачи. Во-первых, задают точку отсчёта
чётности. Во-вторых, определяют, какие недели колледж выложил: во вкладке
«Неделя» кнопка появляется только для них. Сейчас это 31.08–05.09
и 07.09–12.09. Добавит колледж лист с новыми датами — кнопка появится
сама, править код не нужно. Текущая неделя добавляется всегда: если
таблицы отстанут от календаря, сайт продолжит показывать и сегодняшний
день, и эту неделю целиком.

Список опубликованных недель лежит в `docs/data/schedule.json` (поле `weeks`)
и печатается в выводе `tools/check.py`.

## Лишняя вкладка «2 неделя (2)»

В `БД ЭкБ ОИСиР РУПО ИСиП ОИБАС.xlsx` и `ДОШ НАЧ.xlsx` рядом с листом
«2 неделя» лежит копия «2 неделя (2)». Разбор берёт исходный лист.

Так решено не наугад. Правки колледж вносит в лист с обычным именем, а копия
осталась в том виде, в каком её сняли: в оригинале **178 пар, у которых
проставлена аудитория, а в копии на том же месте пусто** — и ни одной пары,
где было бы наоборот. Проверяется это же и по-другому: 09.09.2026 в 13:43 UTC
в облаке обновился `ДОШ НАЧ.xlsx`, сборка его забрала, и в расписании не
изменилось ни одной пары — правка легла в лист, который тогда пропускался.

Пока копия лежит в таблице, любая правка второй недели рискует потеряться —
достаточно, чтобы её внесли не в тот лист. Лишнюю вкладку стоит удалить.

## Особенности исходников, которые сервис обходит

* В `АФК ФК.xlsx` есть объединение ячеек вида `1:1` (целая строка) — openpyxl
  на нём падает, поэтому книга переупаковывается с удалением таких записей.
* В строку «Преподаватель» иногда попадает название дисциплины или пометка
  «замена Иванов И.И.» — первое в поле преподавателя не показывается,
  второе разбирается на фамилию и отметку «Замена».
* Опечатки в инициалах (`Суфиянова А,З.`, `Аллагулова А.А`) приводятся
  к единому виду, иначе один человек попадал бы в список дважды.
* Иногда в книге появляется лишний лист-копия: рядом с `2 неделя` возникает
  `2 неделя (2)`. Оба относятся к одной неделе, и если разобрать их вместе,
  каждая пара попадёт в расписание дважды. Берётся ровно один лист — какой,
  задаёт `SHEET_PREFERENCE` в `app/config.py` (`first` — исходный, `last` —
  копия), про остальные пишется предупреждение. Берём исходный: копию завели
  и забыли, правки идут в лист с обычным именем. Правильное решение —
  удалить лишнюю вкладку в самой таблице.
* Пару, которая есть только у первой подгруппы, в таблице нередко оставляют
  необъединённой — выглядит она тогда почти как обычное занятие всей группы.
  Различаются они шириной строки преподавателя (две колонки против четырёх),
  по ней разбор и решает. На сегодняшних таблицах таких ячеек 92: 90 —
  практика первой подгруппы, 2 — общее занятие без объединения. Без этой
  проверки вторая подгруппа видела бы у себя чужую практику: у 4 ДИ А это
  шесть пар подряд с утра, тогда как её собственная начинается в 14:05
  и в другой аудитории.
* В `ДИ ТИК ПК.xlsx` две разные группы названы `3 ТИК А`. Вторая из них —
  это `3 ТИК Б`; переименование задано в `GROUP_RENAMES` (`app/config.py`).
  Когда опечатку поправят в самой таблице, строку оттуда можно убрать:
  дубля не станет и правило просто перестанет срабатывать. Сработавшие
  переименования видны в предупреждениях на странице «О расписании».

## Проверка разбора

После изменения формата таблиц в колледже полезно прогнать диагностику —
она покажет, сколько занятий и групп нашлось в каждом файле и что выглядит
подозрительно:

```bash
python tools/check.py            # по файлам из data/raw
python tools/check.py --download # предварительно скачав из облака
```

## Когда расписание обновлялось

Главная страница показывает, когда сборка последний раз забирала таблицы
из облака — поле `updated_at` в `docs/data/schedule.json`. Ту же дату берут
подвал и полоска «нет сети», чтобы сайт не называл двух разных дат про одно
и то же.

Время ставится на **каждом** запуске, даже когда в расписании ничего
не поменялось. Значит, файл каждый раз отличается от предыдущего, и Actions
коммитит его каждые полчаса — по сайту сразу видно, что обновление живо
и ходило в облако. Плата за это — примерно полсотни автоматических коммитов
в сутки.

У файлов, собранных до появления поля, его нет: тогда строка на главной
не показывается, а подвал берёт дату сборки.
